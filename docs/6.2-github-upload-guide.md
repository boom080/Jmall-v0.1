# 6.2 GitHub 上传说明

## 上传前检查

```cmd
git --version  & REM 检查 Git 是否安装
gh --version  & REM 检查 GitHub CLI 是否安装
gh auth status  & REM 检查 GitHub CLI 是否已登录
git status  & REM 查看当前 Git 状态
git remote -v  & REM 查看是否已有远程仓库
git ls-files | findstr /i ".env"  & REM 检查 env 文件是否已被 Git 跟踪
git status --ignored  & REM 查看被忽略文件，确认 .env.local 被忽略
```

如果 `gh auth status` 失败，先执行：

```cmd
gh auth login  & REM 登录 GitHub CLI
```

## 确认 .env.local 未被 tracked

```cmd
git ls-files | findstr /i ".env.local"  & REM 确认 .env.local 没有被跟踪
```

如果看到 `.env.local`、`ai-services/.env.local` 或 `docker/local/.env.local`：

```cmd
git rm --cached .env.local  & REM 只从 Git 跟踪中移除，不删除本地文件
git rm --cached ai-services/.env.local  & REM 只从 Git 跟踪中移除，不删除本地文件
git rm --cached docker/local/.env.local  & REM 只从 Git 跟踪中移除，不删除本地文件
git status  & REM 再次确认状态
```

## 初始化 Git

如果当前目录还不是 Git 仓库：

```cmd
git init  & REM 初始化 Git 仓库
git branch -M main  & REM 设置主分支为 main
```

如果已经是 Git 仓库，不要重复破坏历史，只检查当前分支和远程：

```cmd
git branch --show-current  & REM 查看当前分支
git remote -v  & REM 查看远程仓库
```

## 使用 GitHub CLI 创建 private 仓库

```cmd
gh repo create jrunmall-ai-rag --private --source=. --remote=origin  & REM 创建 GitHub private 仓库并绑定 origin
```

如果 origin 已存在，先确认地址：

```cmd
git remote -v  & REM 查看当前 origin
```

如果 origin 不是目标仓库，不要直接覆盖，先确认是否需要更换远程。

## 绑定已有远程仓库

如果 GitHub CLI 不可用，但已经有仓库地址：

```cmd
git remote add origin 你的GitHub仓库地址  & REM 绑定已有 GitHub 远程仓库
```

如果 origin 已存在但地址错误：

```cmd
git remote set-url origin 你的GitHub仓库地址  & REM 确认无误后再修改 origin 地址
```

## 首次 commit

当前工作区如果存在大量历史删除或无关改动，不要直接执行 `git add .`。应只添加确认范围内的文件，例如：

```cmd
git add .gitignore README.md docs/6.2-github-safety-check.md docs/6.2-jrunmall-resume-summary.md docs/6.2-jrunmall-interview-qa.md docs/6.2-github-upload-guide.md docs/screenshots/README.md  & REM 只添加本次文档和安全规则
git status  & REM 再次确认暂存文件
git commit -m "docs: prepare jrunmall ai rag project for github"  & REM 提交 README 和文档整理
```

## push 到 GitHub

```cmd
git push -u origin main  & REM 推送到 GitHub main 分支
```

如果 push 失败，不要强行继续。先检查：

- GitHub CLI 是否登录。
- origin 是否是目标仓库。
- 当前账号是否有权限。
- 远程仓库是否存在。
- 当前分支是否是 `main`。

## 检查 GitHub 页面没有泄露密钥

上传后检查：

1. GitHub 仓库文件列表中没有 `.env.local`、`ai-services/.env.local`、`docker/local/.env.local`。
2. 搜索仓库内 `API_KEY`、`sk-`、`password`、`secret`、`token`。
3. README 和 docs 中只出现占位符，不出现真实 Key。
4. `.env.example` 和 `.env.local.example` 中只包含模板值。

## 如果误提交 .env.local

未 push：从暂存区或最近 commit 移除，然后 amend 或重新提交。

已 push：立即轮换泄露密钥，停止继续上传，并按 GitHub 官方敏感数据处理流程清理历史。
