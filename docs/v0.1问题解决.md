# Jmall v0.1 问题解决

> 版本状态：已完成  
> 版本目标：跑通 AI 电商模拟平台的核心技术和业务链路

## 1. 商城基础链路缺失

### 遇到的问题

项目需要同时支持商家上架和买家模拟购物，但最初缺少能够完整演示的商品、店铺、购物车、订单和用户资产闭环。

### 使用的技术

- Vue 3、TypeScript、Pinia 和 Element Plus 构建前端。
- Spring Boot、MyBatis-Plus 和 MySQL 承载用户、商品、店铺、订单等业务。
- Redis 保存登录态关联数据、缓存和异步任务状态。
- JWT 完成用户身份校验。

### 达到的效果

- 用户可以注册、登录并自动获得店铺。
- 商家可以创建和管理商品。
- 买家可以浏览、收藏、加购、下单和模拟支付。
- 金币、签到、排行和收藏形成了可演示的游戏化闭环。

## 2. AI 上架能力只是单次文案生成

### 遇到的问题

单次调用模型只能返回一段文案，无法展示调研、知识检索、文案、审核和平台适配之间的协作关系。

### 使用的技术

- 使用 LangGraph 编排市场调研、RAG 检索、文案生成、合规审核和平台风格适配。
- 市场调研与 RAG 检索并行执行，完成后再进入文案生成。
- 使用 Tavily 或 Qwen 联网能力获取市场信息。
- 支持淘宝、京东、拼多多、苏宁和小红书风格输出。

### 达到的效果

- 从商品基本信息可以执行一条完整的 Multi-Agent 上架流程。
- 用户能够看到不同 Agent 的进度和阶段结果。
- 同一份商品资料可以生成多个平台风格的内容。

## 3. 模型容易把外部资料当成商品事实

### 遇到的问题

市场趋势、RAG 文档和模型常识可能被写成当前商品的材质、认证、销量、功效或服务承诺，形成幻觉和发布风险。

### 使用的技术

- 在 Prompt 中区分商家事实、市场资料和知识库参考。
- 使用 Fact Guard 清理无依据的高风险声明。
- 合规 Agent 检查绝对化用语、价格异常和信息缺失。
- 将无法确认的内容放入待商家确认项。

### 达到的效果

- 市场趋势不再直接作为当前 SKU 属性发布。
- 未提供的认证、销量、功效和保修等内容会被拦截或降级。
- 模型在信息不足时能够输出待确认提示，而不是完全静默编造。

## 4. Agent 长任务缺少实时反馈

### 遇到的问题

完整 Agent 链路耗时较长，普通 HTTP 请求会让用户误以为页面卡死，刷新或断线后也难以恢复进度。

### 使用的技术

- 使用 SSE 推送任务创建、Agent 进度、局部结果和最终结果。
- 使用 Redis Job Store 保存任务状态和已完成节点。
- 支持前端根据 Job ID 恢复未消费结果。
- 对可独立执行的市场调研和 RAG 节点进行并行化。

### 达到的效果

- 用户可以实时看到 Agent 正在执行的阶段。
- 网络中断或刷新后能够恢复任务结果。
- 并行节点减少了完整流程的等待时间。

## 5. 模型成本和外部服务不稳定

### 遇到的问题

不同模型的价格、速度和稳定性不同；没有 API Key 或联网搜索失败时，项目也需要能够继续本地演示。

### 使用的技术

- 抽象 OpenAI-compatible Provider，支持 DeepSeek、Qwen 和 Mock。
- 按 strong、medium、cheap 分层配置不同 Agent 的模型。
- 记录 Token、Agent 维度成本和任务成本。
- 搜索和模型失败时提供安全降级结果。

### 达到的效果

- 不配置真实模型也能使用 Mock 模式完成本地联调。
- 可以按任务复杂度切换模型，避免所有节点都使用高成本模型。
- 任务结果能够展示模型、Token、成本和降级状态。

## 6. 多服务系统难以验证和观察

### 遇到的问题

Java、Python、Vue、MySQL、PostgreSQL、Redis 和 Go 同时运行后，问题定位和回归验证成本较高。

### 使用的技术

- 使用 Docker Compose 统一编排服务。
- PostgreSQL + pgvector 保存和检索 RAG 文档。
- Prometheus 和 Grafana 提供 Agent 指标与基础展示；Java 和 Go 指标尚未完整接通。
- Java、Python、前端和 Go 分别建立自动化测试。
- 使用端到端脚本验证核心业务链路。

### 达到的效果

- 项目可以通过 Docker Compose 统一启动。
- Agent 调用、成本和部分服务状态具有基础可观测性。
- 核心功能具备可重复的自动化和端到端验证方式。

## v0.1 遗留问题

- 用户输入很少时，系统仍会生成看似完整的商品内容。
- 商品保存后直接进入发布状态，缺少草稿和发布门槛。
- 用户没有商品图时，缺少真正可用的图片搜索或生成流程。
- 技术能力已经跑通，但商品产物还不足以让用户放心发布。

以上问题进入 v0.2 解决。
