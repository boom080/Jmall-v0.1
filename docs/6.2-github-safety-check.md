# 6.2 GitHub 上传安全检查

## 不能上传的文件

- `.env`
- `.env.local`
- `**/.env.local`
- `ai-services/.env.local`
- `docker/local/.env.local`
- 任何真实 API Key、数据库密码、OSS Secret、token、证书或私钥文件
- `*.key`、`*.pem`、`*.p12`、`*.crt`
- `.venv/`、`venv/`、`node_modules/`、`target/`、`dist/`、`build/`、`logs/`、`*.log`
- `.idea/`、`.vscode/`、`__pycache__/`、`.pytest_cache/`、`.mypy_cache/`

## 可以上传的文件

- `.env.example`
- `.env.local.example`
- Java/Python/Vue/Go 源码
- `README.md`
- `docs/` 下不包含真实密钥的说明文档
- `resource/db/` 下的建表脚本和非敏感 seed 数据
- `scripts/` 下不写死真实密码或 API Key 的本地脚本

不使用旧 Git 历史的原因：

- 原始工程历史中包含旧课程资料、历史源码和不属于当前 Jrunmall 主线的内容。
- 旧历史曾出现疑似 secret/token 的课程资料片段，不适合直接 push 到新的公开 GitHub 仓库。
- 当前目标是展示可运行的 Jrunmall AI/RAG 项目，而不是迁移旧 GuliMall 课程仓库。

采用干净初始提交的原因：

- 避免把旧课程资料、旧前端、旧构建产物和历史敏感片段带入新仓库。
- 让 GitHub 仓库首个提交只包含当前项目主线，便于 README、docs、源码和启动脚本对应。
- 保留原始本地目录不变，降低误删本地配置和历史资料的风险。

1. `git ls-files | findstr /i ".env.local"` 没有输出。
2. `git status --ignored` 中 `.env.local`、`ai-services/.env.local`、`docker/local/.env.local` 显示为 ignored。
3. README 和 docs 中没有真实 API Key、真实数据库密码或真实公网数据库地址。
4. 不要使用 `git add .` 提交未确认范围，当前工作区存在大量与本文档任务无关的历史删除记录。

## 如果误提交 .env.local

如果 `.env.local` 已被暂存但还没提交：

```cmd
git rm --cached .env.local
git rm --cached ai-services/.env.local
git rm --cached docker/local/.env.local
git status
```

如果已经 commit 但还没有 push：

```cmd
git rm --cached .env.local
git commit --amend
```

如果已经 push：

1. 立即撤销/轮换泄露的 API Key、数据库密码或 OSS Secret。
2. 停止继续 push。
3. 使用 GitHub 官方敏感数据处理流程和历史清理工具从历史中移除。
4. 不能只靠普通删除文件解决历史泄露问题。
