## 原 4 个阻断案例的修复结果

四个案例均使用名称“保温水杯”、品类“家居日用”。修复后运行中的免费 HTTP 体检接口与本地测试得出相同结果。

| 案例 | 关键输入 | 修复前 | 修复后实际 |
|---|---|---|---|
| R1 主观评价伪装规格 | 规格：`很棒；喜欢`；人群：`学生` | `ready=true`，85 分，无追问 | `needs_input`，55 分，缺少事实并追问 |
| R2 参数明确未知 | 规格：`材质未知；容量未知`；人群：`学生` | `ready=true`，85 分，无追问 | `needs_input`，55 分，缺少事实并追问 |
| R3 人群明确未知 | 规格：`304不锈钢；500毫升`；人群：`不知道呢` | `ready=true`，85 分，无追问 | `needs_input`，65 分，缺少人群并追问 |
| R4 描述否定事实 | `不知道材质型号，也没有尺寸重量等信息，具体商品功能暂时不了解，只知道适合学生使用。` | `ready=true`，85 分，无追问 | `needs_input`，55 分，缺少事实并追问 |

修复位置：`jmall-agent/app/agents/input_gate.py`。

- `_known_clauses` 逐句/项排除未知、待确认、缺少信息与疑问；不简单过滤所有“不/无”字。
- `_has_concrete_marker` 要求具体值、数量或可识别特征，不再只凭“材质/型号/尺寸”关键词放行。
- `_grounded_facts` 剔除评价和人群填充，`_has_facts` 跨字段合并去重，只用有效内容计算条数与长度。
- `_has_audience` 排除未知/否定人群，同时保留明确给出的非枚举职业；同一修复被免费体检、生成、预览与搜图入口复用。

修复验收：上述 4 个案例均转为 `needs_input` 并指出正确缺失项；既有 12 个有效品类样本继续通过；新增 4 × 5 个入口测试验证免费体检、图入口、单独文案、平台预览与搜图拒绝路径。30 个独立语义样本和 15 个填充/跨字段/空白字符样本验证相近错误表达及正常输入。没有修改原反例预期、跳过测试或硬编码四句完整字符串。

实际运行服务另外执行 14 条 HTTP 断言：原 4 个反例、只有名称/品类、正常表格、真实否定属性、已知事实带未知附加项、跨字段事实、已知/未知混合段落，以及 4 个插入空格/零宽字符的变体；14/14 通过，LLM Token 增量为 0。运行容器与仓库中的门禁代码 SHA-256 一致。

## 本轮验证边界

- 本轮不是完整浏览器端到端自动化；现有 `--demo` 只打印人工演示清单，不会自动完成上传、风险确认、发布成功页和买家下单。
- 正式回归使用 Mock 模型/图片服务/业务数据库；不证明 Qwen/DeepSeek 实际文案质量、Google 搜图相关性、真实 MySQL 事务与并发行为。
- 订单服务虽实现了非已发布商品的拦截，但未发现对应的 `OrderServiceTest`；购物车测试通过不能代替订单链路验收。登录拦截器与真实 API 发布门禁也需补集成验证。
- Job 恢复测试使用 FakeRedis，只证明数据结构和所有权逻辑，不证明真实 Redis 重启、跨进程和并发恢复。前端防重复操作也不能代替服务端重复请求与扣费幂等性的并发测试。
- 五个平台的单 Skill 用例验证各自 prompt、调用次数与输出契约；尚不能据此宣称真实模型整条生成链路已完成端到端验收。
- 性能指标已有采集点，但本轮未做负载测试，不能据此承诺 Agent 首事件 P95 <3 秒、真实搜图 P95 <8 秒或生产可用率。
- 有效样本正确率、对抗样本拦截率只能报告所测试的有限集合，不代表所有开放输入。
- 本轮只读运行检查：Java 健康检查 UP；Java/Agent 的 Prometheus 抓取 `up=1`。Go 抓取仍为 0，为已知未接通部分，未作为 v0.2 新增模块的验收通过项。
